# 溯源验真

生成的成品**不往画面里嵌任何水印**（画面就等于「直接重编码一次」的结果），溯源信息**只写在文件元数据里**。共四个字段：

| 字段 | 值 |
| --- | --- |
| 软件开发人 | 秋秋 |
| 工具 | RandomDanceGen |
| 序列号 | `RDG-yyyyMMdd-XXXXXX`（每次生成唯一） |
| 生成时间 | `yyyy-MM-dd HH:mm:ss` |

这四个字段拼成一行，写进元数据的 `comment`：

```text
RandomDanceGen|软件开发人：秋秋|工具：RandomDanceGen|序列号：RDG-20260916-A1B2C3|生成时间：2026-09-16 11:19:05
```

同时写入 `album` = `RandomDanceGen`。

## 在哪儿看

| 格式 | 位置 |
| --- | --- |
| **MP4** | 文件右键 → 属性 → 详细信息 → **备注**（`comment`）/ **专辑**（`album`） |
| **MP3** | 同上；但 Windows 属性页的「备注」对 MP3 显示为空（原因见下） |

::: warning MP3 的已知限制
ffmpeg 的 ID3v2 写入器只接受「4 字符且以 `T` 开头」的标签名，标准注释帧 `COMM` 会被挡掉；而 Windows 属性页的「备注」恰好只认标准注释帧 —— 所以 **MP3 在属性页里看不到这条注释**。

信息其实仍写在文件里，用验真工具或 ffmpeg 都能读回。
:::

拼接时会清掉源片段的元数据（`-map_metadata -1`），所以成品里**只保留这一份**随舞溯源信息，不会混进 B站源自带的标签。

## 验真工具：RDG验真

配套的独立验真程序（GUI + 命令行），只具备**读元数据**的能力，不携带任何「嵌入 / 还原」水印的手法。

**图形界面**：双击 `RDG验真.exe`，选择文件即可。

**命令行**：

```bash
RDG验真.exe "D:\output\随舞视频_20260916_111905.mp4"
```

**判定口径**：解析 `comment` 中的四个字段，**四项齐全**才判为 ✓「溯源信息完整」；缺任何一项一律报 ✗「未找到」—— 宁可报「无」，也不拼出一份半真的溯源信息。GUI 与命令行共用同一套判定。

> 历史说明：v3.6.0 之前的成品曾带过一层自研**隐形水印**，这些**旧成品依然可以正常验真** —— 它们的元数据里同样有这四个字段。
